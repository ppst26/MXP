## เป้าหมาย

แปลงบริการคุย Krungthai BizNext จาก Node/Express+SQLite เป็น Go ตามมาตรฐาน `go-template`  
สัญญาที่ส่งไปหาธนาคารต้องเหมือนเดิมทุกไบต์ ส่วน API ที่เปิดให้คนเรียกเราเปลี่ยนได้

## ทำอะไร

- เก็บ device (ล็อกอินนิติบุคคล + PIN + token) ใน PostgreSQL
- ล็อกอินอัตโนมัติแล้วทำงานต่อเมื่อ token หมดอายุ
- ดูบัญชี ประวัติรายการ โอนเดี่ยว โอนชุด bulk อนุมัติรายการ
- ยืนยันตัวตนผู้เรียกด้วย `X-API-Key` จาก config
- เรียกบริการเข้ารหัส PIN แยกต่างหาก

## ไม่ทำอะไร

- ไม่มีร้านค้า ไม่มีสมุดบัญชี ไม่มีฝาก-ถอนของเกตเวย์
- ไม่เข้ารหัส PIN ตอนเก็บ (บันทึกเป็นงานอนาคต)
- ไม่มี Redis — บริการนี้ไม่มี session ของคน

## กฎเหล็ก

- header, content-type, ลำดับ query string, ค่า `null` / ว่าง / ไม่ส่งคีย์ ต้องเหมือน Node ที่วัดจากสายจริง
- อย่าเดารูปแบบ response ของธนาคาร ต้องเทียบกับสิ่งที่จับบนสายได้
- `session.Do` ไม่ล็อกงานขนาน — สองคำสั่งโอนพร้อมกันบน device เดียวสร้างออเดอร์ชนกันได้

## เมื่อจบแล้วได้อะไร

มีบริการ Go ที่ล็อกอินบัญชีนิติบุคคลจริง แล้วโอน / อ่านยอด / อ่านสเตตเมนต์ได้  
เกตเวย์ทุกเฟสต่อไปเรียกผ่านชั้นนี้ ไม่คุยธนาคารตรง

## ขั้นถัดไป

P1+P2 สร้างร้านค้า กองบัญชี บจก. และสมุดบัญชี โดยชี้ `bank_accounts.device_id` มาที่ตาราง `devices` ของเฟสนี้
