# P1 + P2 — ร้านค้า ความปลอดภัย กองบัญชี สมุดบัญชี

| | |
|---|---|
| วันที่ | 26 ส.ค. 2026 |
| สถานะ | อนุมัติดีไซน์ |
| ไฟล์ต้นฉบับ | `docs/docs/superpowers/specs/2026-08-26-maxpay-merchant-ledger-design.md` |
| ขั้นลำดับ | 1 — รากฐานเกตเวย์ ยังไม่ขยับเงินเอง |
| แผนย่อย | P1 ร้านค้า+กุญแจ → P2a กองบัญชี บจก. → P2b สมุดบัญชีคู่ |

## เป้าหมาย

ให้เกตเวย์มีร้านค้าที่รับใช้ กุญแจที่ยืนยันคำขอ กองบัญชีนิติบุคคลที่เงินจริงวิ่งผ่าน และสมุดบัญชีคู่ที่บอกว่าเงินเป็นของใคร  
ฝาก (P3) และถอน (P4) ต้องลงสมุดนี้เท่านั้น ห้ามคิดยอดเอง

## ทำอะไร

**P1**

- ต้นไม้ร้านค้า ROOT / RESELLER / DIRECT อัตราฝาก-ถอน ส่วนต่างตัวแทน
- กุญแจ 4 ตัว: `merchantId`, `clientId`, `x-api-key`, `secretKey`
- ลายเซ็น HS256 ใช้ครั้งเดียว กัน replay
- กันเลขออเดอร์ซ้ำต่อร้าน (`idempotency`)
- ล็อกอินหลังบ้าน แอดมินแพลตฟอร์มและยูสเซอร์ร้าน

**P2a**

- กองบัญชี 3 ชั้น: รับ (INBOUND) / พัก (VAULT) / จ่าย (OUTBOUND)
- 1 Merchant มีได้หลายบัญชี บจก. — แบบ dedicated หรือแชร์คลัสเตอร์
- 1 บัญชีผูก device (ล็อกอินธนาคาร) ได้ และมีได้หลายยูสเซอร์ฝั่งธนาคาร
- คิวงาน outbox ใน Postgres

**P2b**

- สมุดบัญชีคู่ ผลรวมบรรทัดต้องเป็นศูนย์ ฐานข้อมูลบังคับตอน commit
- ยอดร้านค้า = operate + parking + freeze (freeze รวมเงินที่กันไว้รอถอน)
- คำนวณค่าธรรมเนียมและส่วนคืนตัวแทนเป็นบรรทัดในใบเดียวกัน

## ไม่ทำอะไร

| ยังไม่มี | เฟส |
|---|---|
| สร้างฝาก QR จับคู่สเตตเมนต์ | P3 |
| สั่งถอนและยิงธนาคาร | P4 |
| ประวัติ webhook เต็มรูป inquiry API | P5 |
| กวาดเงิน หมุนบัญชี เติมบัญชีจ่าย | P6 |
| หน้าจอรายการธุรกรรม | P7 |

## กฎเหล็ก

- เงินเป็นทศนิยม ห้าม float
- เขียนสมุดได้ทางเดียวคือ `ledger.Post` ในทรานแซกชันเดียวกับงานต่อเนื่อง
- ยอดธนาคาร (`bank_balance`) กับยอดในสมุดแยกกัน ถ้าไม่ตรงแปลว่ามีเงินที่ระบบไม่รู้จัก
- ลายเซ็นกันคำขอซ้ำ กันเลขออเดอร์ซ้ำกันการจ่ายซ้ำ — ธนาคารไม่มี idempotency ของตัวเอง
- DIRECT สร้างลูกสายไม่ได้ อัตราลูกต้องไม่ต่ำกว่าต้นทุนพ่อ

## เมื่อจบแล้วได้อะไร

สร้างร้าน ออกกุญแจ เซ็นคำขอแล้วระบบรับหรือปฏิเสธได้  
ผูกบัญชี บจก. อ่านยอดจริงจากธนาคาร ลง adjustment แล้วยอดขยับถูกต้องทุกชั้นของต้นไม้  
ยังไม่มีเงินฝากหรือถอนอัตโนมัติ

## ขั้นถัดไป

P3 เปิดบิลฝาก ดึงสเตตเมนต์ จับคู่ แล้วเรียก `PostDepositMatched`
