## เป้าหมาย

ร้านสั่งจ่ายเงินให้ใครสักคนได้ ตัดยอดที่ใช้ได้ทันทีที่รับคำสั่ง คืนเลขอ้างอิงให้เช็คสถานะ  
เฟสนี้ไม่คุยธนาคารเลย จึงทดสอบกับฐานข้อมูลจริงได้โดยไม่เสี่ยงบัญชีบริษัท

## ทำอะไร

- `POST /api/v1/payout/create` มีลายเซ็น กันเลขออเดอร์ซ้ำ
- ตาราง `payouts` และวงจรสถานะ
- กันเงิน **ยอด + ค่าธรรมเนียมร้าน** ผ่าน `PostPayoutCreated`
- เก็บ `reserved_fee` ตามที่สมุดกันจริง ไม่คำนวณใหม่ตอนจบ
- เลือกบัญชีต้นทางจาก config ตั้งแต่ตอนสร้าง เพราะคำตอบต้องบอกบัญชีที่จะจ่าย
- `GET` ดูรายการเดียวและดูเป็นหน้า — ไม่ต้องใช้ลายเซ็น เพราะไม่ขยับเงิน

## ไม่ทำอะไร

- ไม่เรียกธนาคาร ไม่เช็คชื่อ ไม่ใช้ PIN ไม่สร้างออเดอร์โอน
- ไม่มีเวิร์กเกอร์ส่งเงิน (P4b)
- ไม่เรียก `PostPayoutCompleted` / `PostPayoutFailed`
- ไม่มี webhook (P4c)
- ไม่วัด buffer บัญชีจ่ายจากตัวเลขเก่าค้าง — แย่กว่าไม่มี เพราะคนเชื่อมัน

## กฎเหล็ก

- `confirmed_at IS NULL` = ยังไม่สั่งธนาคาร คืนเงินได้  
  `confirmed_at IS NOT NULL` = เงินอาจออกแล้ว ต้องมีหลักฐานเชิงบวกเท่านั้นจึงปิดยอด
- กันเงินทั้งยอดและค่าธรรมเนียม เช็กตอนล็อกแถว operate ในทรานแซกชันเดียวกัน
- สองใบถอนของร้านเดียวกันต้องเข้าคิวที่ล็อก operate ใบที่สองอ่านยอดหลังใบแรกกันเงินแล้ว
- เงินไม่พอต้อง rollback ทั้งแถวและใบสมุด ไม่เหลือซาก
- `payout.enabled` ปิดเป็นค่าเริ่มต้น

## เมื่อจบแล้วได้อะไร

ร้านสร้างรายการถอนได้ เงินถูกกันใน `pending_payout` รายการค้างที่ `PENDING` ตลอดไปจนกว่า P4b จะส่ง  
ไม่มี merchant คนไหนถึง endpoint นี้ได้ก่อนเปิดสวิตช์

## ขั้นถัดไป

P4b ส่งเงินที่กันไว้ และเขียน `bank_order_id` / `confirmed_at` ตอนที่ธนาคารได้รับคำสั่งจริง
