# ส่วน A — กติการ่วมทั้งระบบ

## A1. เป้าหมาย

ให้แอดมินแพลตฟอร์มเห็นว่าการโอนออก **ยังไหลอยู่ไหม ต้นทุนธนาคารเท่าไหร่ ชุดไหนค้าง และใบไหนค้าง** โดยไม่ต้องเปิดฐานข้อมูล

หน้านี้ตอบได้ภายในไม่กี่วินาที:

1. บัญชีต้นทางยังจ่ายได้หรือไม่ (สวิตช์, สถานะบัญชี, ยอดจริง, เพดานวัน)
2. มีคิวใบค้าง หรือชุดค้างที่คนต้องดูหรือไม่
3. ช่วงที่เลือก สำเร็จเท่าไหร่ ล้มเท่าไหร่ **ค่าธรรมเนียมโอนธนาคารเท่าไหร่**
4. เปิดใบถอนเจอร้าน ยอด ผู้รับ บัญชีต้นทาง และชุดที่ใบนั้นสังกัด
5. เปิดชุดโอนเจอออเดอร์ธนาคาร จำนวนใบในชุด ยอดรวม ค่าโอนต่อใบ และสถานะรายใบ

## A2. ขอบเขต

### อยู่ในเฟสนี้

- หน้า **ภาพรวมโอนออก** (`/payouts/overview`) เป็น landing ของเมนูหลัก **โอนออก**
- หน้า **รายการใบถอน** (`/payouts`) และรายละเอียดหนึ่งใบ (เข้าจากแถว ไม่ใส่ไซด์บาร์)
- หน้า **รายการชุดโอน** (`/payouts/batches`) และรายละเอียดหนึ่งชุด — แพลตฟอร์มแอดมินเท่านั้น ซับเมนูโชว์เมื่อมีตารางชุด
- ไซด์บาร์ต้นไม้ตาม A4 ไม่มีตารางรวมใบกับชุด
- API หลังบ้านสำหรับหน้าเหล่านี้ (session auth)
- ค่าธรรมเนียมโอนธนาคารเป็นต้นทุนเฟิร์สคลาส: **ข้ามธนาคาร 5.00 บาท ต่อ 1 รายการ, ในธนาคารเดียวกัน 0.00 บาท**
- ตัวเลือกร้านแบบค้นหา จัดกลุ่มตามตัวแทน เลือกโหนดแล้วได้ทั้งสาย
- ตัวกรองชุดเดียวกันขับ dashboard กับหน้ารายการใบ

### ไม่อยู่ในเฟสนี้

- หน้าจอฝาก / statement / กระทบยอดขาเข้า
- ปุ่มปิด `NEEDS_REVIEW`, ปุ่มยิงชุดใหม่, ปุ่มคืนเงิน, ปุ่มปรับสมุด, ปุ่มทิ้งออเดอร์ที่ธนาคาร
- Webhook, สลิป QR, `callbackResponse` (P5)
- Auto-sweep, หมุนบัญชี, แจ้งเตือน buffer อัตโนมัติ (P6)
- Dual-control / Maker-Approver ของบัญชี บจก.
- คลัง BI, export ไฟล์, ส่งอีเมลรายงาน
- Merchant-facing API ใหม่

## A3. ข้อบังคับตลอดทั้งเฟส

- เงินใน API เป็นสตริงทศนิยม ห้าม `float64`
- โซนเวลาของทุกช่วงวันที่คือ **`Asia/Bangkok` (UTC+7)**
- แอดมินแพลตฟอร์มเห็นทุกร้าน ตัวแทนและยูสเซอร์ร้านเห็นเฉพาะ subtree ผ่าน `adminmerchant.EnsureVisible`
- ห้ามส่ง PIN, API key, secret, credential บัญชีธนาคาร
- ห้ามใช้ `GET /accounts/cashflow` และห้ามใช้ `isCompleted` ของธนาคารเป็นสัญญาณสำเร็จ
- ค่าบริการเกตเวย์ (`reserved_fee`) กับค่าธรรมเนียมโอนธนาคาร (`bank_fee`) **ห้ามบวกเป็นก้อนเดียว**
- ค่าโอนธนาคารคิด **ต่อใบ** ไม่ต่อชุด — การ์ดชุดโชว์ผลรวมของใบ ไม่ใช่อัตราต่อชุด
- หน้านี้เป็นแบบอ่านอย่างเดียว ไม่มี side effect ต่อสมุดหรือธนาคาร
- เมื่อมี `bank_bulk_order_id` แล้ว **ห้ามมี UI ที่พาไปส่งชุดนั้นซ้ำ**

## A4. โครงสร้างหน้าและเมนู

จัดตาม **ทิศเงิน** ไม่ตามชนิดวิดเจ็ต  
เมนูหลัก = สิ่งที่คนเปิดทุกกะ · ซับเมนู = ชนิดแถวที่ค้นได้ · หน้ารายละเอียดเข้าได้แค่จากแถวหรือการ์ด

### A4.1 เส้นทาง

ห้าเส้นทาง แยกชัด

```
/payouts/overview          ภาพรวมโอนออก          (default เมื่อกดเมนูหลัก)
/payouts                   รายการใบถอน
/payouts/:referenceId      รายละเอียดหนึ่งใบ      (ไม่อยู่ในไซด์บาร์)
/payouts/batches           รายการชุดโอน          (แพลตฟอร์มแอดมิน, หลังมีตารางชุด)
/payouts/batches/:id       รายละเอียดหนึ่งชุด    (ไม่อยู่ในไซด์บาร์)
```

ตัวกรองช่วงเวลา + ร้าน + เส้นทาง + สถานะใบ ใช้ชื่อพารามิเตอร์เดียวกันบนภาพรวมและหน้ารายการใบ แต่**ตำแหน่งบนจอไม่เหมือนกัน**

- `/payouts` — แถวตัวกรองหลักอยู่บนสุดของหน้า ตาม A4.6
- `/payouts/overview` — แถวเดียวกันเป็น**หัวก้อนสรุปตามช่วงเวลา** ไม่วางเหนือก้อนเรียลไทม์ (ดูส่วน B)

แถวตัวกรองหลัก **ไม่ห่อ Card** — ใช้ control ลอยบนพื้นหลัง (ดู A4.6)  
**ซ้าย:** ร้าน (Command popover หรือ disabled ถ้าร้าน DIRECT) · **ขวา (ชิดขวาเสมอ):** เม็ดช่วง · เส้นทาง (หน้าที่มี) · date range picker  
สถานะใบ / ค้นหาอ้างอิงอยู่แถวสองของหน้ารายการใบ — ห่อ **Card surface** แยก ไม่ปนกับแถววันที่

สวิตช์เดโมบ้าน (send ปิด, ยอดเก่า, ไม่มีบัญชีต้นทาง, ยอดไม่พอคิว) **ไม่ใช่ตัวกรองของคนใช้จริง** — อยู่ปุ่ม **จำลอง** บนแถบหัวจอ เปิดเป็นแผง แอดมินเท่านั้น มุมมองร้านไม่มีปุ่มนี้

หน้ารายการชุดมีตัวกรองของตัวเอง (สถานะชุด, เลขออเดอร์ธนาคาร) ไม่ใช้ `merchantId` เป็นตัวกรองหลัก เพราะหนึ่งชุดมีได้หลายร้าน

กดเมนูหลัก **โอนออก** แล้วไป `/payouts/overview` ไม่ไปตารางใบ

### A4.2 ไซด์บาร์ — เมนูหลักและซับเมนู

```
โอนออก                         ← เมนูหลัก กดแล้วไปภาพรวม
  ├ ภาพรวม                     ← /payouts/overview
  ├ รายการใบถอน                ← /payouts
  └ ชุดโอน                     ← /payouts/batches     แอดมินเท่านั้น · หลัง P4c
รับเงิน                          ← ซ่อนทั้งเฟสนี้ คนละทิศเงิน ห้ามเป็นลูกของโอนออก
สมุดบัญชี / บัญชีต้นทาง / ร้านค้า ← นอกขอบ P7a ไม่ใส่ในเมนูเฟสนี้
```

| รายการไซด์บาร์ | ใครเห็น | เมื่อไหร่โชว์ | ไฮไลต์เมื่ออยู่หน้า |
|---|---|---|---|
| โอนออก (กลุ่ม) | ทุกบทบาทที่เข้า BO ได้ | ตลอดเฟสนี้ | ทุกหน้าใต้กลุ่มนี้ |
| ภาพรวม | แอดมินทั้งจอ · ร้านได้โซน 2–3 ตาม E3 | ตลอด | `/payouts/overview` |
| รายการใบถอน | แอดมิน + ร้าน (ใบในสาย) | ตลอด | `/payouts` และ `/payouts/:referenceId` |
| ชุดโอน | แพลตฟอร์มแอดมินเท่านั้น | มีตาราง `payout_batches` แล้ว | `/payouts/batches` และ `/payouts/batches/:id` |

กติกาไฮไลต์: เปิดรายละเอียดใบแล้วซับเมนู **รายการใบถอน** ยัง active · เปิดรายละเอียดชุดแล้ว **ชุดโอน** ยัง active  
หน้ารายละเอียด **ไม่มีรายการในไซด์บาร์** ไม่ทำเมนูลอย "รายละเอียดใบ / รายละเอียดชุด"  
รูปแบบ icon + chevron ดู A4.7

ร้านและตัวแทน **ไม่เห็น** ซับเมนูชุดโอน เข้า URL ตรง = 404 ตาม E3

ก่อนมี `payout_batches` ซ่อนซับเมนูชุดโอนทั้งก้อน ไม่โชว์หน้าว่าง ไม่โชว์ศูนย์ปลอม

ทางที่ไม่ใช้:

- แบนสามเมนูพี่น้อง (ภาพรวม · ใบ · ชุด) ที่รากไซด์บาร์ — รากเต็มเร็ว และไม่บอกว่าเป็นโมดูลเดียวกัน
- เมนู "ทั้งหมด" ที่ปนแถวใบกับแถวชุดในตารางเดียว — ดู A4.4
- แท็บบนหน้าเดียวแทนซับเมนู — ใช้ได้ถ้าไซด์บาร์สั้นมาก แต่ URL กับสิทธิ์ร้าน/แอดมินยุ่งกว่าต้นไม้นี้ จึงไม่ใช้ในเฟสนี้

เฟสถัดไปใส่ **รับเงิน** เป็นเมนูหลักคนละต้นไม้ ไม่เป็นลูกของโอนออก

### A4.3 สัดส่วนข้อมูลต่อหน้า

ลำดับอ่านบนภาพรวมคงที่: บัญชียังจ่ายได้ไหม → มีของค้างไหม → ช่วงนี้เป็นยังไง  
บนจอแบ่งสองก้อนหัวขนาดเท่ากัน: **ภาพรวมเรียลไทม์** แล้ว **สรุปตามช่วงเวลา** (ดูส่วน B)

| หน้า | สัดส่วนที่ควรเห็น | ไม่โชว์ที่นี่ |
|---|---|---|
| ภาพรวม | โซน 1 ~¼ · โซน 2 ~¼ · โซน 3 ~½ รวมตารางร้านที่ต้องดู 8 แถวใต้คู่เทียบ | ตารางยาวใบละแถว, ตารางชุด |
| รายการใบ | แถบสรุปบางๆ ด้านบน · ตารางเป็นหลัก | การ์ดบัญชีต้นทาง, รายการชุด |
| รายการชุด | แถบสรุปชุด · ตารางชุด | กรองร้านเป็นตัวกรองหลัก (ไป `/payouts?batchId=&merchantId=` แทน) |
| รายละเอียดใบ/ชุด | หนึ่งอ็อบเจ็กต์เต็มฟิลด์ | KPI ช่วงวันที่, การ์ดคิวทั้งระบบ |

โซน 2 กับโซน 3 คนละชนิดข้อมูล: โซน 2 ไม่ตัดวันที่ (สแนปชอตคิวตอนนี้, poll 15 วินาที, ไม่มี websocket) โซน 3 ตัด `from`–`to` — ดูส่วน B

อยากไล่ใบในชุดหนึ่ง ให้กรอง `?batchId=` บนหน้ารายการใบ ไม่สร้างหน้าที่สาม

### A4.4 ห้ามตารางรวมใบกับชุด

ไม่มีเมนูและไม่มีหน้า "รายการทั้งหมด" ที่แถวชุดกับแถวใบอยู่ตารางเดียวกัน

| | รายการใบ | รายการชุด |
|---|---|---|
| หนึ่งแถวคือ | คำสั่งถอนของร้านหนึ่ง | ออเดอร์ bulk หนึ่งครั้งที่ธนาคาร |
| ร้านในแถว | ร้านเดียว | ปนหลายร้านได้ |
| สถานะ `FAILED` | ใบนั้นไม่ผ่าน | ชุดโดนปฏิเสธก่อนมีเลขออเดอร์ ใบถูกปล่อยกลับคิว **ไม่ใช่ล้มต่อร้าน** |
| ตัวกรองหลัก | ร้าน / สถานะใบ / เส้นทาง | สถานะชุด / เลขออเดอร์ธนาคาร |
| ใครเห็น | แอดมิน + ร้าน (ใบตัวเอง) | แอดมินเท่านั้น |

ใบบางใบไม่มีชุดเลย (เช็คชื่อแล้วบัญชีไม่มี, ยังรอส่ง, บัญชีต้นทางไม่พอจึงไม่ถูกหยิบ) — ตารางรวมจะไม่รู้ว่าแถวนั้นคือใบเดี่ยวหรือหัวชุด  
จุดรวมสัญญาณทั้งสองแบบคือ **ภาพรวม** เป็นการ์ด ไม่ใช่ตารางปนชนิด รายละเอียดเพิ่มในส่วน D1

## A5. ค่าธรรมเนียมโอนธนาคาร (ต้นทุนบ้าน)

P4c กำหนดไว้แล้วและเฟสนี้ไม่เปลี่ยน:

| | ค่าบริการเกตเวย์ | ค่าธรรมเนียมโอนธนาคาร |
|---|---|---|
| ฟิลด์ | `payouts.reserved_fee` | `payouts.bank_fee` (หลัง P4c) |
| จ่ายโดย | ร้าน (กันไว้ตอนสร้าง) | **แพลตฟอร์ม** ลง `HOUSE_EXPENSE` |
| อัตรา | ตามสายร้าน | **0.00 ในธนาคารเดียวกัน, 5.00 ข้ามธนาคาร ต่อ 1 รายการ** |
| แหล่งจริงตอนปิดยอด | ค่าที่สมุดกันตอนสร้าง ห้ามคำนวณใหม่ | `itemTransactionFee` จากธนาคาร ห้ามคิดเอง |

### A5.1 นิยามเส้นทาง

```
route = SAME_BANK   เมื่อ recipient_bank_code = บัญชีต้นทางของใบนั้น.bank_code
route = INTERBANK   เมื่อไม่เท่า
```

```
SAME_BANK_FEE    = 0.00
INTERBANK_FEE    = 5.00    # บาท ต่อ 1 รายการ ห้ามคูณกับยอดโอน ห้ามคิดต่อชุด
```

บัญชีต้นทางเป็นกรุงไทย ใบที่ผู้รับเป็นกรุงไทยจึงเป็น `SAME_BANK`

`payout_batches.total_fee` คือค่าที่ธนาคารเสนอทั้งชุด (nullable จนกว่าจะมี) **ไม่ใช่** แหล่งจริงของต้นทุนบ้าน แหล่งจริงคือผลรวม `payouts.bank_fee` รายใบหลังปิดยอด

### A5.2 สองตัวเลขที่ต้องโชว์คู่กัน ห้ามเหลือตัวเดียว

**ก. ต้นทุนที่เกิดแล้ว (`incurredBankFee`)**

```
นับใบ INTERBANK ที่เงินอาจถูกคิดแล้ว:

  COMPLETED ทั้งหมดที่ route = INTERBANK
  FAILED ที่ bank_fee > 0
  ไม่นับ PENDING, PROCESSING, REJECTED, NEEDS_REVIEW

เมื่อมี payouts.bank_fee:
  incurredBankFee = SUM(bank_fee) ของใบที่นับ

เมื่อยังไม่มี:
  incurredBankFee = COUNT(COMPLETED ที่ INTERBANK) × 5.00
  ป้าย: "ประมาณการ 5.00 บาท/รายการข้ามธนาคาร — ยังไม่มีค่าจากธนาคาร"
```

**ข. ต้นทุนผูกกับคิวที่ยังไม่จบ (`exposedBankFee`)** — ประมาณการ ไม่ใช่รายจ่ายในสมุด

```
exposedBankFee = COUNT(PENDING หรือ PROCESSING ที่ INTERBANK) × 5.00
```

ห้ามรวมเข้า `incurredBankFee`

### A5.3 การ์ดบน dashboard

ชื่อการ์ด: **ค่าธรรมเนียมโอนธนาคาร**

| บรรทัด | ค่า |
|---|---|
| ต้นทุนที่เกิดแล้ว | `incurredBankFee` |
| จำนวนใบข้ามธนาคารที่คิดแล้ว | `incurredInterbankCount` × 5.00 |
| ในธนาคารเดียวกันช่วงนี้ | `sameBankCount` ใบ · 0.00 |
| ประมาณการคิวที่ยังไม่จบ | `exposedBankFee` สีรอง |

เมื่อมี `bank_fee` จริง: `ส่วนต่าง = incurredBankFee − (incurredInterbankCount × 5.00)` ถ้าไม่เป็นศูนย์ให้ไฮไลต์

ห้ามมีคอลัมน์หรือการ์ด "ค่าธรรมเนียมรวม" ที่บวก `reserved_fee + bank_fee`

| WebSocket / push | **ไม่มีในเฟสนี้** | ไม่มี |

เรียกว่า realtime ในความหมายปฏิบัติการ (ดูคิวตอนนี้) ไม่ใช่สตรีมมิลลิวินาที
ถ้า poll ค้าง ใบใหม่จะยังไม่ขึ้นการ์ดจนกว่าจะรอบถัดไป — ยอมรับได้เพราะคนใช้หน้านี้ไล่ของค้าง ไม่ได้กดเทรด

จอเป็น **การ์ดมินิมอล** ไม่ใช่แถวยาว: ตัวเลขใหญ่ ป้ายสั้น สีเงียบเมื่อเป็น 0 สีเหลือง/แดงเมื่อมีของที่ต้องดู
คลิกการ์ดไปหน้ารายการพร้อมตัวกรองนั้น และขยายช่วงวันที่เป็น 30 วัน เพื่อไม่ให้ใบค้างเมื่อวานถูกตัวกรอง "วันนี้" บัง

เงินที่ถูกกันอยู่ (`PENDING` + `PROCESSING`) อยู่โซนนี้ ไม่ใช่โซน 3 เพราะเป็นยอดปัจจุบันเช่นกัน

### B2.1 แถวใบ

| การ์ด | นับ | บรรทัดรอง | สีเมื่อ > 0 |
|---|---|---|---|
| รอส่ง | ใบ `PENDING` | ยอดรวม · อายุใบเก่าสุด | เทา |
| กำลังส่ง | ใบ `PROCESSING` ก้อนเดียว | ถ้ามีใบที่เลขออเดอร์แล้วแต่ยังไม่ `confirmed_at` เขียน "ห้ามส่งซ้ำ N" | เหลืองเมื่อมีห้ามส่งซ้ำ |
| รอคนดู | ใบ `NEEDS_REVIEW` | ยอดรวม | แดง |
| เงินที่กันไว้ | `SUM(amount + reserved_fee)` ของ PENDING+PROCESSING | ยอดปัจจุบันทั้งขอบเขตที่มองเห็น | เทา — ไม่ใช่เตือน แค่ตัวเลขค้าง |

ห้ามแยกการ์ดสามใบสำหรับ PROCESSING ย่อย (ยังไม่มีออเดอร์ / ยังไม่ยืนยัน / รอผล) — ยัดในบรรทัดรองของการ์ดกำลังส่ง

คลิกการ์ดใบไป `/payouts` พร้อมตัวกรองสถานะนั้น (การ์ดเงินที่กันไว้ไปสถานะ PENDING+PROCESSING)

เมื่อมีแถวสมุดร้านตาม B2.3 **ซ่อน** การ์ดเงินที่กันไว้ของ B2.1 เพื่อไม่ให้คนอ่านสองตัวเลขคนละสูตรบนจอเดียวกัน

หลัง P4c ใบ `PROCESSING` ส่วนใหญ่หมายถึง "อยู่ในชุดที่ยังไม่ปิดยอด"

### B2.2 แถวชุด (แพลตฟอร์มแอดมิน, มีหลัง P4c)

คลิกไป `/payouts/batches` ไม่ไปหน้ารายการใบ

| การ์ด | นับ | บรรทัดรอง | สีเมื่อ > 0 |
|---|---|---|---|
| ชุดรอส่ง | ชุด `PENDING` | รวมใบในชุด · รวมยอด | เทา |
| ชุดระหว่างทาง | `SENDING` + `SENT` | ถ้ามี `bank_bulk_order_id` เขียน "ห้ามส่งซ้ำ" | เหลือง |
| ชุดต้องดู | ชุด `NEEDS_REVIEW` หรือค้างเกิน `stuck_batch_after` | จำนวนชุด | แดง |

ถ้ายังไม่มีตาราง `payout_batches` ซ่อนทั้งกลุ่ม B2.2 ไม่โชว์ศูนย์ปลอม

ห้ามมีปุ่ม "ล้มรายการ" "คืนเงิน" "ถือว่าสำเร็จ" "ส่งชุดซ้ำ" บนโซนนี้

### B2.3 สมุดร้าน — ใช้ได้ / กันถอน (ร้าน DIRECT ร้านเดียว)

โชว์เมื่อขอบเขตเป็น **ร้าน DIRECT ร้านเดียว** (ยูสเซอร์ร้านเสมอ, หรือแอดมินที่เลือกโหนด DIRECT)  
ทุกร้านหรือตัวแทนทั้งสาย = **ไม่โชว์** ห้ามบวก `operate` ข้ามร้าน

แถวนี้อยู่บนสุดของโซน 2 ก่อนการ์ดคิวใบ ค่าไม่ตัด `from`/`to`

| การ์ด | บัญชีสมุด | คลิก |
|---|---|---|
| ใช้ได้ | `MERCHANT_OPERATE` | ไม่คลิก |
| กันไว้รอถอน | `MERCHANT_PENDING_PAYOUT` | `/payouts` สถานะ PENDING + PROCESSING + NEEDS_REVIEW |
| พักไว้ | `MERCHANT_PARKING` | โชว์เมื่อ > 0 |
| อายัด | `MERCHANT_FREEZE` | โชว์เมื่อ > 0 — ข้อพิพาทอย่างเดียว ไม่รวมกันถอน |

`pendingPayout` = `SUM(amount + reserved_fee)` ของใบร้านนั้นที่สถานะยังกันเงิน (`PENDING`, `PROCESSING`, `NEEDS_REVIEW`)  
`FAILED` / `REJECTED` / `COMPLETED` คืนหรือตัดออกจาก `pending_payout` แล้ว ห้ามนับ

ยอดร้านตาม PRD: `balance = operate + parking + freezeBalance` โดย `freezeBalance = MERCHANT_FREEZE + MERCHANT_PENDING_PAYOUT`  
บนจอโอนออก **ห้าม** รวมอายัดกับกันถอนเป็นการ์ดเดียว เพราะคนใช้หน้านี้ต้องแยกคิวถอนออกจากข้อพิพาท

ห้ามคิด `operate` จากใบในช่วงวันที่เลือก

## B3. โซน 3 — สรุปตามช่วงเวลา (ยอดช่วงที่เลือก + การเทียบ)

หัวก้อนบนจอคือ **สรุปตามช่วงเวลา** แถวแรกเป็น `DateMerchantFilter` แล้วจึงเป็นการ์ดสรุปและกราฟ  
ทุกตัวเลขในก้อนนี้ตัดด้วยตัวกรอง (ช่วงเวลา, ร้าน, เส้นทาง, สถานะใบ)  
นับใบตาม `payouts.created_at` ไม่ใช่ตามเวลาปิดยอด

### การ์ดสรุป

| การ์ด | สูตร |
|---|---|
| จำนวนใบ | `COUNT(*)` ในชุดที่กรอง |
| ยอดโอน | `SUM(amount)` |
| สำเร็จ | จำนวนและยอด `COMPLETED` |
| ล้ม | `FAILED` + บรรทัดรอง `REJECTED` |
| อัตราสำเร็จ | `COMPLETED / (COMPLETED + FAILED)` ไม่นับ pending, processing, rejected, needs_review |
| ค่าธรรมเนียมโอนธนาคาร | ตาม A5.3 กว้างกว่าการ์ดอื่น |
| ค่าบริการร้าน | `SUM(reserved_fee)` การ์ดแยก |
| ชุดในช่วงนี้ | จำนวนชุดที่ `created_at` อยู่ในช่วง · แยก SETTLED / ยังไม่จบ / NEEDS_REVIEW — การ์ดเล็ก คลิกไปหน้ารายการชุด |

เทียบเปอร์เซ็นต์ช่วงก่อนเฉพาะ สำเร็จ / ยอดโอน / ต้นทุนธนาคาร

### สี่คู่เทียบ (บังคับ)

**คู่ 1 — ช่วงนี้ vs ช่วงก่อน** การ์ดซ้าย ~70% ยอดเงิน COMPLETED · การ์ดขวา ~30% จำนวนใบ / จำนวนชุด (สลับได้ ชุดเฉพาะแอดมิน) รายชั่วโมงถ้าช่วง ≤ 2 วัน นอกนั้นรายวัน

**คู่ 1ข — ค่าธรรมเนียมแยกการ์ด 50/50** ซ้ายโดนัท `reserved_fee` ต่อร้าน (MDR) · ขวาแท่ง `5.00 × จำนวนใบข้ามธนาคาร` ต่อร้านในช่วง แอดมินเท่านั้น · ห้ามบวกสองการ์ด · คลิกกรองร้าน  
โดนัท: hover = ชื่อร้าน + ยอด · รายการขวาเป็นยอดรวมต่อร้าน ไม่ใช่ %  
แท่งค่าโอน: hover = ยอดเท่านั้น ไม่โชว์ `N × 5.00` (สูตรอยู่หัวการ์ดและเชิงอรรถ) · สีแท่งแยกตามร้าน · กราฟธนาคารปลายทางในคู่ 3 ใช้สีตามรหัสธนาคาร

**คู่ 2 — ในธนาคาร vs ข้ามธนาคาร** ตาราง 2 แถว ไม่ใช่พายชาร์ต คอลัมน์ค่าโอนธนาคารเป็น 0.00 / incurred

**คู่ 3 — ธนาคารปลายทาง + อัตราสำเร็จ** สัดส่วน `recipient_bank_code` ของใบในช่วง (จำนวน ยอด %) คนละแกนกับคู่ 2 · กราฟอัตราสำเร็จอยู่แถวเดียวกัน ไม่โชว์กรวยสถานะ อายุคิว และรายการสาเหตุบนโซนนี้ (ล้มอ่านจาก KPI และหน้ารายการใบ · คิวอยู่โซน 1 และตารางร้าน)

**คู่ 4 — ยอดบัญชีต้นทาง vs คิว vs เพดานวัน** แถบตอนนี้เท่านั้น ห้ามวาดกราฟยอดธนาคารย้อนหลัง
ถ้า `bank_balance < ยอดคิว + min_balance` เขียนว่าบัญชีต้นทางไม่พอจ่ายทั้งคิว — P4c จะส่งเท่าที่พอแล้วคิวที่เหลือจะนิ่ง

## B4. ร้านที่ต้องดู (แพลตฟอร์มแอดมินเท่านั้น)

ตารางสั้นใต้โซน 3 บนภาพรวมเจ้าของระบบ — **สะพานไปกรองร้าน** ยังไม่ใช่จอร้าน

ตอบ: ร้านไหนดูดคิว ล้มชื่อ ค้างคนดู หรือกันเงินไว้เยอะ โดยไม่ต้องเดาในตัวเลือกทุกร้าน

ร้านและตัวแทน **ห้ามเห็น** ก้อนนี้ใน API เป็น `null`

### แถวและคอลัมน์

สูงสุด **8 แถว** เฉพาะร้าน DIRECT ไม่โชว์แถวตัวแทน  
เรียงคะแนนเตือนก่อน แล้วค่อยยอดสำเร็จ — ร้านใหญ่เงียบไม่บังร้านเล็กที่ไฟไหม้

```
alertScore =
  NEEDS_REVIEW ตอนนี้ × 100
  + (อายุใบรอส่งเก่าสุด ≥ 30 นาที ? 50 : 0)
  + FAILED ในช่วงที่เลือก × 10
  + PENDING ตอนนี้
```

| คอลัมน์ | ที่มา |
|---|---|
| ร้าน | ชื่อ · รหัส |
| สำเร็จช่วงนี้ | จำนวนและยอด `COMPLETED` ตาม `from`–`to` |
| ล้ม | `FAILED` ในช่วง (ไม่รวม REJECTED) |
| รอคนดู | ใบ `NEEDS_REVIEW` ตอนนี้ ไม่ตัดวันที่ |
| รอส่ง | ใบ `PENDING` ตอนนี้ |
| กันไว้ | `SUM(amount + reserved_fee)` ของ PENDING+PROCESSING ตอนนี้ |
| เก่าสุด | อายุใบ PENDING เก่าสุด นาที ว่างถ้าไม่มีคิว |

### พฤติกรรม

- คลิกแถว = ใส่ `merchantId` ของร้านนั้นบนภาพรวมเจ้าของ **ไม่กระโดดไปจอร้าน**
- กรองอยู่ที่ร้าน DIRECT ร้านเดียว = **ซ่อนตาราง** มีข้อความว่าดูการ์ดด้านบน
- กรองตัวแทน = ตารางเหลือแต่ร้านลูกในสาย
- ทุกร้าน = ทั้งระบบ สูงสุด 8 แถวตามคะแนน
- ไม่ใช่ตารางใบ ไม่ใช่หน้าร้านค้าทั้งร้อยแถว

รายการที่ร้านจะไม่เห็น (ล็อกก่อนทำจอร้าน): โซน 1 ทั้งก้อน · การ์ดชุด · ค่าโอนธนาคาร · คู่ 4 บัญชีต้นทาง · ตารางนี้ · ยอด `bank_balance`

| สาเหตุ | `failure_reason` | ตัดข้อความยาว |

อย่าใส่ `callback_url` ในตาราง

## C4. รายละเอียดหนึ่งใบ `/payouts/:referenceId`

หัวกระดาษ: สถานะใบ, ยอด, ร้าน, เวลาสร้าง

1. **ผู้รับ** — บัญชี, ธนาคาร, ชื่อที่ส่ง, ชื่อที่ธนาคารตอบ, เบอร์, เส้นทาง, ค่าโอนธนาคาร (แอดมิน)
2. **บัญชีต้นทาง** — `systemBankData` ของใบนี้ ไม่ใช่ config ปัจจุบัน
3. **เงิน** — `amount`, `reserved_fee`, ยอดที่กันไว้; `bank_fee` เฉพาะแอดมิน
4. **ชุดที่สังกัด** — ถ้า `batch_id` ว่าง เขียน "ยังไม่เข้าชุด" (ยัง PENDING หรือล้มก่อนเข้าชุด) ถ้ามี: สถานะชุด, `package_ref_no`, `bank_bulk_order_id`, `bank_item_id`, ลิงก์ไปหน้าชุดสำหรับแอดมิน
5. **ธนาคารระดับใบ** — `bank_order_id` (เส้นเดี่ยว P4b ถ้ายังมี), `confirmed_at`, `attempts`, `next_attempt_at`
6. **ไทม์ไลน์** — จุดที่รู้จริงเท่านั้น: `created_at` → PENDING, `confirmed_at` ถ้ามี, สถานะจบที่ `updated_at` ห้ามแทรก PROCESSING ถ้าไม่มีคอลัมน์เวลา
7. **สมุด** — `PAYOUT_CREATED` / `COMPLETED` / `FAILED`
8. **สาเหตุ** — `failure_reason` ทั้งข้อความ

`callback_url` โชว์เป็นข้อความได้เฉพาะแพลตฟอร์มแอดมิน ห้ามเป็นลิงก์คลิก

```
processSeconds ของใบ COMPLETED ที่มี confirmed_at
  = confirmed_at − created_at
คำอธิบาย: เวลาถึงจุดที่ธนาคารรับคำสั่ง ไม่ใช่เวลาเงินเข้าบัญชีผู้รับ
ไม่โชว์ processSeconds ของใบที่ไม่ COMPLETED
```

# ส่วน D — ชุดโอน (Bulk / Batch)

หลัง P4c เกตเวย์ไม่ส่งทีละใบเป็นหลัก ร้านสั่งถอนเป็นใบ ระบบรวมใบเข้า **หนึ่งออเดอร์ bulk ของกรุงไทย** แล้วปิดยอดรายใบจากสถานะรายการย่อยของธนาคาร

หน้านี้มีไว้ตอบ: **ชุดนี้ไปถึงธนาคารหรือยัง, เงินอาจออกแล้วหรือยัง, ใบในชุดจบครบหรือยัง, ค่าโอน 5 บาทเกิดกี่ใบ**

ก่อนตาราง `payout_batches` มีจริง ซับเมนู **ชุดโอน** ซ่อนจากไซด์บาร์ ไม่ทำหน้าว่าง — ดู A4.2

## D1. ทำไมต้องแยกจากหน้ารายการใบ

กติกาเมนูและเหตุผลตารางรวมอยู่ที่ A4.2–A4.4 ตารางนี้ย้ำความหมายของแถว

| | ใบถอน | ชุดโอน |
|---|---|---|
| หนึ่งแถวคือ | คำสั่งถอนของร้านหนึ่ง | ออเดอร์ bulk หนึ่งครั้งที่ธนาคาร |
| มีได้หลายร้านในแถวเดียว | ไม่ | ได้ — กองบัญชีจ่ายรวม |
| ค่าโอน 5 บาท | ต่อแถว | ผลรวมของแถวลูก ไม่ใช่อัตราต่อชุด |
| สถานะ `FAILED` | ใบนั้นไม่ผ่าน | ชุดถูกธนาคารปฏิเสธ **ก่อน** มีเลขออเดอร์ ใบในนั้นกลับไป PENDING ไม่ใช่ล้มต่อร้าน |
| สิทธิ์ร้าน | เห็นใบตัวเอง | **ไม่เห็นหน้าชุด** เพราะชุดปนร้านอื่นได้ |

## D2. สิ่งที่ชุดหนึ่งถืออยู่ (คอลัมน์จริง)

จาก `payout_batches` ตาม P4c:

| ฟิลด์ | ความหมายบนจอ | โชว์ที่ |
|---|---|---|
| `id` | รหัสชุดในเกตเวย์ | ตาราง, URL |
| `status` | วงจรชุด ตาม D3 | ทุกที่ |
| `item_count` | จำนวนใบที่ **เข้าชุดได้** | ตาราง — ไม่นับใบที่เช็คชื่อแล้วล้มก่อนเปิดชุด |
| `total_amount` | ผลรวม `amount` ของใบในชุด | ตาราง — ไม่รวมค่าบริการร้าน ไม่รวมค่าโอนธนาคาร |
| `total_fee` | ค่าที่ธนาคารเสนอทั้งชุด | ตาราง ถ้าว่างแสดง "ยังไม่ทราบ" — **ไม่ใช่** ต้นทุนบ้านที่ใช้ลงสมุด |
| `bank_account_id` | บัญชีต้นทางที่ส่งชุดนี้ | รายละเอียด |
| `bank_bulk_order_id` | เลขออเดอร์ bulk ที่ธนาคาร | ตาราง+รายละเอียด — **ว่าง = ยังส่งซ้ำได้, มีค่า = จุดห้ามส่งซ้ำ** |
| `package_ref_no` | เลขอ้างอิงชุดจากธนาคาร | ตาราง ใช้ค้น |
| `failure_reason` | คำของธนาคารเมื่อชุด FAILED ก่อนมีออเดอร์ | ตาราง |
| `created_at` | เวลาเปิดชุด | ตาราง |
| `sent_at` | เวลาเริ่มส่ง (เข้า SENDING) | รายละเอียด |
| `confirmed_at` | เวลาที่ธนาคารรับคำสั่งชุด — เงินอาจออกแล้ว | รายละเอียด เหลืองถ้ามีแล้วยังไม่ SETTLED |
| `settled_at` | เวลาปิดชุด (ทุกใบในชุดมีผลแล้ว) | รายละเอียด |

ใบในชุดถือเพิ่ม: `batch_id`, `bank_item_id`, `bank_fee`

## D3. วงจรสถานะชุด

```
PENDING ──claim──> SENDING ──ธนาคารรับชุด──> SENT ──ใบในชุดจบครบ──> SETTLED
   │                  │                         │
   │                  │                         └── มีใบที่ยังไม่รู้ผล ──> NEEDS_REVIEW
   │                  ├── ตายและยังไม่มี bank_bulk_order_id ──> กลับ PENDING (ส่งใหม่ได้)
   │                  └── ตายแต่มีเลขออเดอร์แล้ว ──> ค้าง SENDING ให้ reconciler ถาม ห้ามส่งซ้ำ
   └── ธนาคารปฏิเสธก่อนมีออเดอร์ ──> FAILED
```

| `status` | คำบนจอ | ความหมายที่ทีมต้องจำ |
|---|---|---|
| `PENDING` | รอส่ง | เปิดชุดแล้ว ยังไม่ยิงธนาคาร ส่งใหม่ได้ |
| `SENDING` | กำลังส่ง | กำลังคุยธนาคาร ดูว่ามี `bank_bulk_order_id` หรือยัง |
| `SENT` | ส่งแล้วรอปิดยอด | ธนาคารรับชุดแล้ว ปิดยอดรายใบอยู่ |
| `SETTLED` | ปิดยอดแล้ว | ทุกใบในชุดเป็น COMPLETED หรือ FAILED ที่รู้จักแล้ว ไม่มี NEEDS_REVIEW |
| `NEEDS_REVIEW` | รอตรวจสอบ | มีอย่างน้อยหนึ่งใบที่รหัสธนาคารไม่รู้จัก ชุดไม่ปิดเอง |
| `FAILED` | ส่งชุดไม่สำเร็จ | เกิดได้แค่ก่อนมีเลขออเดอร์ ใบในชุดถูกปล่อยกลับ PENDING **ห้ามนับใบเหล่านั้นว่าล้ม** |

## D4. สิ่งที่อยู่ในชุด vs ไม่อยู่ — ห้ามหาใบผิดที่

| ใบแบบนี้ | อยู่ใน `payout_batches` ไหม | ไปดูที่ |
|---|---|---|
| เข้าชุดแล้วกำลังปิดยอด | อยู่ สถานะใบ `PROCESSING` | หน้าชุด + ตารางใบ `?batchId=` |
| ธนาคารบอกใบสำเร็จ/ล้มในชุด | อยู่ | หน้าชุด แถวลูก |
| เช็คชื่อแล้วบัญชีไม่มี ก่อนเปิดชุด | **ไม่อยู่** ใบเป็น `FAILED` ไม่มี `batch_id` | หน้ารายการใบ สาเหตุจากธนาคาร |
| เรียกเช็คชื่อไม่ติด | **ไม่อยู่** ใบยัง `PENDING` | คิวรอส่ง |
| คิวที่เงินบัญชีต้นทางไม่พอ จึงไม่ถูกใส่ชุดนี้ | **ไม่อยู่** ยัง `PENDING` | โซน 2 รอส่ง + คู่ 4 บัญชีไม่พอ |
| ชุด FAILED ก่อนมีออเดอร์ | ใบถูกถอดกลับ `PENDING` | หน้าชุดโชว์เหตุผลชุด ใบไปคิวรอส่ง ไม่ใช่ตารางล้ม |

หน้าชุดต้องมีข้อความใต้ตารางลูก: "ใบที่ล้มตอนเช็คชื่อหรือยังไม่ถูกหยิบจะไม่โชว์ในชุดนี้"

## D5. หน้ารายการชุด `/payouts/batches`

แพลตฟอร์มแอดมินเท่านั้น ยูสเซอร์ร้านได้ 404 ทั้งหน้า

### D5.1 ตัวกรองชุด

| พารามิเตอร์ | ความหมาย |
|---|---|
| `from` `to` | `payout_batches.created_at` โซนไทย กว้างสุด 90 วัน |
| `status` | สถานะชุด ซ้ำได้ ตาม D3 |
| `q` | ตรงทั้งค่า `id` หรือ `bank_bulk_order_id` หรือ `package_ref_no` |
| `stuck` | true = SENDING/SENT เกิน `stuck_batch_after` |

ไม่มี `merchantId` — ถ้าต้องการใบของร้านหนึ่งในชุด ให้ไป `/payouts?batchId=&merchantId=`

เรียง `created_at desc` · หน้าละ 20

### D5.2 แถบสรุปชุด (ตามตัวกรอง, ทั้งชุดไม่ใช่หน้าปัจจุบัน)

```
จำนวนชุด
ใบในชุดทั้งหมด SUM(item_count)
ยอดโอนในชุด SUM(total_amount)
ชุดที่ยังไม่จบ (PENDING+SENDING+SENT+NEEDS_REVIEW)
ชุด SETTLED
ค่าโอนธนาคารที่เกิดแล้วจากใบในชุดเหล่านี้ ตาม A5.2 ก (ไม่ใช้ SUM total_fee)
```

### D5.3 คอลัมน์ตารางชุด

| คอลัมน์ | จอ |
|---|---|
| เวลาเปิดชุด | `created_at` |
| สถานะชุด | ตาม D3 |
| จำนวนใบ | `item_count` |
| ยอดโอนรวม | `total_amount` |
| ในธนาคาร / ข้ามธนาคาร | นับใบลูกในชุด — คอลัมน์นี้บอกต้นทุน 5 บาทคร่าวๆ |
| ค่าโอนธนาคาร | ผลรวม `bank_fee` ของใบลูกที่คิดแล้ว ถ้าว่างใช้จำนวนใบข้ามธนาคารที่ COMPLETED × 5.00 ติดป้ายประมาณการ **ห้ามใส่ `total_fee` เป็นหลัก** |
| ค่าเสนอจากธนาคาร | `total_fee` บรรทัดรอง สีรอง ถ้าว่างเป็น "—" |
| เลขออเดอร์ธนาคาร | `bank_bulk_order_id` ถ้าว่างป้าย "ยังไม่มี — ส่งใหม่ได้" ถ้ามีป้าย "ห้ามส่งซ้ำ" |
| เลขอ้างอิงชุด | `package_ref_no` |
| ส่ง / ยืนยัน / ปิดยอด | `sent_at` · `confirmed_at` · `settled_at` ค่าว่างเป็น "—" |
| สาเหตุชุด | `failure_reason` |
| อายุถ้าค้าง | โชว์เมื่อ SENDING/SENT เกินเกณฑ์ |

คลิกแถวไปรายละเอียดชุด

## D6. หน้ารายละเอียดชุด `/payouts/batches/:id`

หัวกระดาษ: สถานะชุด, `item_count` ใบ, `total_amount`, เวลาเปิดชุด

ห้ามมีปุ่มกระทำการใดๆ

### บล็อก 1 — สถานะและจุดห้ามส่งซ้ำ

| ช่อง | |
|---|---|
| สถานะชุด | ตาม D3 |
| `bank_bulk_order_id` | ว่าง = ส่งใหม่ได้ · มีค่า = จุดห้ามส่งซ้ำ ไฮไลต์ |
| `package_ref_no` | |
| `confirmed_at` | ถ้ามี คำอธิบาย "เงินอาจออกจากบัญชีต้นทางแล้ว" |
| `failure_reason` | ทั้งข้อความเมื่อ FAILED |

### บล็อก 2 — บัญชีต้นทางของชุด

เลขบัญชี ชื่อ ธนาคาร สถานะบัญชีตอนดู (ของปัจจุบัน) — เชิงอรรถว่าชุดนี้ผูก `bank_account_id` ตอนเปิดชุด

### บล็อก 3 — เงินของชุด (สามก้อนห้ามปน)

| ก้อน | ค่า | หมายเหตุ |
|---|---|---|
| ยอดโอน | `total_amount` | ผลรวมยอดใบ |
| ค่าบริการร้านในชุด | `SUM(reserved_fee)` ของใบลูก | ของร้าน ไม่ใช่บ้าน |
| ค่าโอนธนาคารที่เกิดแล้ว | ตาม A5.2 ก ของใบลูก | บ้านจ่าย ต่อใบข้ามธนาคารละ 5 บาท |
| ค่าเสนอทั้งชุดจากธนาคาร | `total_fee` | สีรอง ยังไม่ใช่สมุด |

ตารางย่อย 2 แถว: ในธนาคาร / ข้ามธนาคาร ของใบในชุดนี้เท่านั้น (จำนวน, ยอด, ค่าโอน)

### บล็อก 4 — ความคืบหน้าใบในชุด

นับจากใบลูกตอนโหลดหน้า:

```
PROCESSING (ยังไม่จบ) | COMPLETED | FAILED | NEEDS_REVIEW
```

ใบในชุดไม่มี `PENDING` (เข้าชุดแล้วเป็น PROCESSING) และไม่มี `REJECTED`
แถบสัดส่วน + ตัวเลข คลิก `NEEDS_REVIEW` กรองตารางลูก

ถ้าชุดเป็น `FAILED` ตารางลูกอาจว่างเพราะใบถูกปล่อยกลับคิว — โชว์ข้อความตาม D4 ไม่โชว์ตารางว่างเฉยๆ

### บล็อก 5 — ตารางใบในชุด

คอลัมน์: อ้างอิงใบ, ร้าน, ยอด, เส้นทาง, ค่าโอนธนาคาร, สถานะใบ, `bank_item_id`, ชื่อผู้รับ, ชื่อที่ธนาคารตอบ, สาเหตุใบ

คลิกอ้างอิงไปหน้ารายละเอียดใบ
เรียงตามลำดับเข้าชุด (FIFO ที่ P4c ใช้ตอนเลือกใบ) ถ้าไม่มีลำดับในคอลัมน์ เรียง `payouts.created_at`

ไม่แบ่งหน้าถ้า `item_count` ไม่เกิน `batch_max_items` ซึ่งเริ่มเล็ก ถ้าเกินค่อยแบ่งหน้า

### บล็อก 6 — ไทม์ไลน์ชุด (จุดที่รู้จริง)

```
created_at     เปิดชุด PENDING
sent_at        เริ่มส่ง SENDING
bank_bulk_order_id ถูกเขียน    จุดห้ามส่งซ้ำ
confirmed_at   ธนาคารรับชุด
settled_at     ปิดชุด SETTLED หรือเข้า NEEDS_REVIEW
```

ห้ามแทรกจุดที่คอลัมน์ว่าง

## D7. สิ่งที่หน้าชุดห้ามมี

- ปุ่มส่งซ้ำ / ยกเลิกออเดอร์ที่ธนาคาร / ทิ้ง DRAFT ที่ธนาคาร
- ปุ่มปิด `NEEDS_REVIEW` ของใบหรือของชุด
- การ์ดค่าธรรมเนียมก้อนเดียวที่บวกค่าบริการร้านกับค่าโอนธนาคาร
- การคิด 5 บาทคูณ `item_count` ทั้งชุด (ใบในธนาคารต้องเป็น 0)
- ให้ยูสเซอร์ร้านเปิดหน้านี้
- นับชุด `FAILED` เป็น "ใบล้ม" ในอัตราสำเร็จของส่วน C

# ส่วน E — สถานะ สิทธิ์ API

## E1. สีและคำสถานะใบ

| `status` | คำบนจอ | สี | ความหมาย |
|---|---|---|---|
| `PENDING` | รอส่ง | เทา | กันเงินแล้ว ยังไม่เข้าชุด / ยังไม่ยิง |
| `PROCESSING` | กำลังส่ง | น้ำเงิน | อยู่ในชุดที่ยังไม่ปิดยอด หรือกำลังโอน |
| `COMPLETED` | สำเร็จ | เขียว | ธนาคารบอกสำเร็จ หรือหลักฐานเดบิตชัด |
| `FAILED` | ไม่สำเร็จ | แดง | ยิงแล้วไม่ผ่าน หรือเช็คชื่อแล้วบัญชีไม่มี |
| `REJECTED` | ไม่รับทำ | ส้ม | ยังไม่ยิงธนาคาร คนละถังกับ FAILED |
| `NEEDS_REVIEW` | รอตรวจสอบ | ม่วง | รหัสธนาคารที่ไม่รู้จัก ห้ามปิดอัตโนมัติ |

เส้นทาง: `ในธนาคาร` เขียวอ่อน, `ข้ามธนาคาร` น้ำเงิน — ข้ามธนาคารไม่ใช่ความผิดปกติ

## E2. สีสถานะชุด

| `status` | คำบนจอ | สี |
|---|---|---|
| `PENDING` | รอส่ง | เทา |
| `SENDING` | กำลังส่ง | น้ำเงิน |
| `SENT` | ส่งแล้วรอปิดยอด | น้ำเงินเข้ม |
| `SETTLED` | ปิดยอดแล้ว | เขียว |
| `NEEDS_REVIEW` | รอตรวจสอบ | ม่วง |
| `FAILED` | ส่งชุดไม่สำเร็จ | ส้ม — คนละความหมายกับใบ FAILED |

## E3. สิทธิ์

| บทบาท | ภาพรวม | รายการใบ | รายละเอียดใบ | รายการชุด / รายละเอียดชุด | ไซด์บาร์ |
|---|---|---|---|---|---|
| แพลตฟอร์มแอดมิน | ทั้งระบบ รวมโซนชุดค้าง | ทั้งระบบ | ทั้งระบบ | ทั้งระบบ | โอนออก → ภาพรวม, รายการใบถอน, ชุดโอน (ชุดโชว์เมื่อมีตาราง) |
| ยูสเซอร์ร้าน / ตัวแทน | โซน 2–3 ของสายตัวเอง ไม่มีชุดค้าง | ใบในสาย | ใบในสาย 404 ถ้านอกสาย | **404 ทั้งหน้า** | โอนออก → ภาพรวม, รายการใบถอน · **ไม่มีชุดโอน** |

ยูสเซอร์ร้านเห็น `batchId` / `packageRefNo` บนใบตัวเองได้ (เป็นเลขอ้างอิงของใบนั้น) กดแล้วไป `/payouts?batchId=` ซึ่ง `EnsureVisible` ตัดเหลือแต่ใบในสาย
ห้ามส่ง `total_amount` ของทั้งชุดให้ร้าน — จะเปิดเผยยอดร้านอื่นในชุดเดียวกัน

ยูสเซอร์ร้านไม่เห็น: ยอด `bank_balance`, เพดานวัน, สวิตช์ส่ง, การ์ดค่าโอนธนาคารทั้งระบบ, คอลัมน์ `bankFee`, หน้าชุด

## E4. API หลังบ้าน

ซองคำตอบ `{ "success": true, "code": 200, "data": {} }`
เงินเป็นสตริง · `amount`/`reserved_fee` สเกล 4 · ค่าโอนธนาคารสเกล 2
รายการมี `pagination: { page, limit, total, pages }`

Query: `from`, `to`, `merchantId`, `route`, `status` (ซ้ำได้) — ไม่รับ `q`

`data` มี `sourceAccount`, `queue`, `period`, `previousPeriod`, `byRoute`, `byRecipientBank`, `timeseries` ตามสัญญาเดิม และเพิ่ม:

```json
    "stuckAfterSeconds": 900

  "batchCount": 3,
  "batchSettledCount": 2,

```

ก่อน P4c ก้อน `queue.batches` เป็น `null` ไม่ใช่ศูนย์ทุกช่อง

# ส่วน F — ส่งมอบ

## F1. สิ่งที่มีในฐานข้อมูลวันนี้ กับสิ่งที่รอ P4c

หน้าใบถอนและ dashboard โซน 1–3 ใช้ได้ตั้งแต่มีตาราง `payouts` ของ P4a/P4b

| ความสามารถ | ก่อน P4c | หลัง P4c |
|---|---|---|
| รายการใบ, สถานะ, กันเงิน, บัญชีต้นทาง | มี | มี |
| เส้นทาง SAME_BANK / INTERBANK | คำนวณจากรหัสธนาคาร | เช่นเดิม |
| ค่าโอน 5 บาท/ใบข้ามธนาคาร | ประมาณการ | `bank_fee` จริง + ส่วนต่างจาก N × 5 |
| หน้าชุด, คอลัมน์ชุด, โซน 2 กลุ่มชุด | **ซ่อนจากเมนู** | โชว์ |
| `package_ref_no`, `bank_item_id`, `total_fee` | ไม่มี | โชว์ |
| ชุด `NEEDS_REVIEW` | ไม่มีแถว | แถวแดง |
| `queue.batches` | `null` | นับจริง |

ห้ามสร้างตารางสรุปแยกสำหรับ dashboard — อ่านจาก `payouts`, `payout_batches`, `bank_accounts`, `bank_account_daily_stats`, `ledger_accounts`
ถ้าช่วง 90 วันช้า ใส่ index `(created_at DESC)` ไม่ทำ pipeline analytics แยก

## F2. สูตรที่ห้ามทำผิด

1. อัตราสำเร็จใบ = `completed / (completed + failed)` ไม่รวม pending, processing, rejected, needs_review และไม่รวมชุด FAILED
2. `route` เทียบรหัสธนาคารผู้รับกับบัญชีต้นทาง **ของใบนั้น**
3. ค่าโอนธนาคาร = ต่อใบ ไม่ต่อบาท ไม่ต่อชุด ไม่คูณ `item_count` ทั้งชุด
4. `incurredBankFee` นับเฉพาะใบที่คิดแล้ว ตาม A5.2 ก
5. ช่วงเวลาใบตัดที่ `payouts.created_at` ช่วงเวลาชุดตัดที่ `payout_batches.created_at` โซนไทย
6. งานค้างโซน 2 ไม่ตัด `from`/`to`
7. ยอดกันเงินเป็นยอดปัจจุบัน ไม่ตัดช่วง
8. ชื่อไม่ตรง = trim แล้วเทียบสตริงตรงตัว
9. ไม่เห็นเดบิต ≠ โอนไม่เกิด — ห้ามมี UI ที่พาไปทางนั้น
10. มี `bank_bulk_order_id` แล้วห้ามส่งชุดซ้ำ และห้ามมีปุ่มที่สื่อว่าทำได้
11. ชุด FAILED ไม่ทำให้ใบเป็น FAILED
12. ต้นทุนบ้านห้ามใช้ `total_fee` เป็นหลัก ใช้ผลรวม `bank_fee` รายใบ
13. ร้านห้ามเห็นยอดรวมทั้งชุด

## F3. สถานะว่างและข้อผิดพลาดบนจอ

| กรณี | จอ |
|---|---|
| ไม่มีใบในช่วง | การ์ด 0 ตารางข้อความไม่พบรายการ |
| ไม่มีชุดในช่วง | ตารางชุดข้อความไม่พบชุด |
| ยังไม่ตั้งบัญชีต้นทาง | โซน 1 ข้อความชัด |
| `send_enabled` ปิด และมี PENDING | แบนเนอร์เหลืองใต้โซน 1 |
| ยอดธนาคารเก่า | แบนเนอร์เหลือง ห้ามอ่านว่าพอจ่าย |
| ชุด SENT/SENDING ค้างเกินเกณฑ์ | แบนเนอร์แดงบน dashboard และหน้าชุด |

ห้ามวาดกราฟชุดว่างเป็นเส้นศูนย์ทั้งแกนโดยไม่มีคำอธิบาย

## F4. งานที่ยอมรับได้ว่าเสร็จ

**ใบและ dashboard**

1. `/payouts/overview` ก้อนเรียลไทม์แล้วก้อนสรุปตามช่วงเวลา ตามส่วน B แล้วตารางร้านที่ต้องดูตาม B4 · ตัวกรองวันที่อยู่หัวก้อนสรุปเท่านั้น
2. การ์ดค่าโอนธนาคารแยกจากค่าบริการร้าน · หัวการ์ดโชว์ N × 5.00 · hover แท่งเหลือแค่ยอด
3. ใบ SAME_BANK ไม่เพิ่มต้นทุนธนาคาร
4. ใบ PENDING INTERBANK ไม่เข้า incurred แต่เข้า exposed
5. ตัวกรองชุดเดียวขยับการ์ดก้อนสรุปกับตารางใบ — ไม่ขยับคิวเรียลไทม์เมื่อเปลี่ยนวันนี้/7 วัน
6. โซนงานค้างนับใบเมื่อวานที่ยัง PENDING แม้ตัวกรองเป็นวันนี้
6b. ตารางใบมีโลโก้จำลอง + เลขบัญชีที่คอลัมน์ผู้รับ ไม่มีคอลัมน์เส้นทาง
7. คลิก NEEDS_REVIEW ของใบไปตารางใบ ไม่มีปุ่มปิดยอด
8. ยูสเซอร์ร้านไม่เห็นยอดบัญชี บจก. การ์ดต้นทุนธนาคาร และหน้าชุด
9. JSON ยอดเงินเป็นสตริง
10. ตัวเลือกร้านเลือกตัวแทนแล้วได้ใบของลูก

**ชุด (เมื่อมี P4c หรือเมื่อเปิดหน้าชุด)**

11. เมนูชุดโชว์เมื่อมีตาราง ซ่อนเมื่อไม่มี ไม่โชว์หน้าว่าง
12. ตารางชุดมีสถานะ, จำนวนใบ, ยอด, เส้นทางใน/ข้าม, ค่าโอนต่อใบรวม, เลขออเดอร์, จุดห้ามส่งซ้ำ
13. รายละเอียดชุดมีตารางใบลูก และข้อความว่าใบที่ล้มตอนเช็คชื่อไม่อยู่ในชุด
14. ชุด FAILED ไม่ไปเพิ่มตัวเลข FAILED ของใบ
15. ไม่มีปุ่มส่งซ้ำเมื่อมี `bank_bulk_order_id`
16. คลิกชุดค้างบน dashboard ไป `/payouts/batches` ไม่ไป `/payouts`
17. ไซด์บาร์เป็นต้นไม้โอนออกตาม A4.2 ไม่แบนสามพี่น้องที่ราก ไม่มีเมนูตารางรวมใบกับชุด
18. หน้ารายละเอียดไม่อยู่ในไซด์บาร์ เปิดใบแล้วไฮไลต์รายการใบถอน เปิดชุดแล้วไฮไลต์ชุดโอน
