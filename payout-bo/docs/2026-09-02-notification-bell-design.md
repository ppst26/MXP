# Design: กระดิ่งแจ้งเตือนใน MaxPay BO

วันที่: 2026-09-02
สถานะ: อนุมัติจากบทสนทนา 2026-09-02 — รอรีวิวสเปกก่อนลงมือทำ

แอป mock ที่ `payout-bo/app` ไม่มี API แจ้งเตือนจริง รายการในกระดิ่งคำนวณจาก `db` ปัจจุบันบวกเหตุการณ์เติมเงินจำลอง

---

## 1. เป้าหมาย

ให้ทั้งแพลตฟอร์มแอดมินและร้านเห็นเรื่องที่ต้องรู้โดยไม่ต้องอยู่หน้าภาพรวมตลอด

- กดกระดิ่งมุมขวาบน (ซ้ายของตัวสลับบทบาท) แล้วเปิด **popover** ไม่ใช่ dialog
- มาสเตอร์เห็นงานระดับชุดโอนและบัญชีต้นทาง (pool)
- ร้านเห็นงานระดับใบโอน สมุดร้าน และเติมเงินของตน
- จุดบนกระดิ่งบอกจำนวนเรื่องที่ **ยังต้องลงมือ** ไม่นับแถวสำเร็จ

## 2. ขอบเขต

อยู่ในรอบนี้

- ปุ่มกระดิ่งทุกหน้าที่ห่อด้วย `Shell`
- popover สองช่วง: ของที่ยังค้าง / เหตุการณ์ล่าสุด
- คลิกแถวแล้วปิด popover แล้วไปหน้าพร้อมตัวกรองหรือรายละเอียด
- seed แถวเติมเงินของร้าน Acme เพราะยังไม่มีหน้า top-up

ไม่อยู่ในรอบนี้

- push, webhook, อีเมล, polling ใหม่
- สถานะอ่านแล้ว / เก็บประวัติ inbox
- รหัสผ่านผิดซ้ำ (มีอยู่แล้วที่หน้าประวัติเข้าระบบ)
- สร้างผู้ใช้ เปลี่ยนชื่อร้าน ปิดบัญชี
- หน้าเติมเงินจริง หรือ API แจ้งเตือน

## 3. ใครเห็นอะไร

ร้านถูก scope ที่ `m-acme` ตาม viewer ปัจจุบัน มาสเตอร์เห็นทั้งบ้าน

### 3.1 ช่วงบน — ยังค้างอยู่ (live)

แถวโชว์เมื่อนับมากกว่าศูนย์ หรือเข้าเกณฑ์ยอดใกล้หมด หายเองเมื่อสถานะกลับมาปกติ

| id | มาสเตอร์ | ร้าน | โทน |
|---|---|---|---|
| `queue` | ชุด `PENDING` | ใบ `PENDING` | ปกติ |
| `waiting` | ชุด `SENDING` หรือ `SENT` | ใบ `PROCESSING` | เตือนถ้ามีชุด `stuck` |
| `review` | ชุด `NEEDS_REVIEW` หรือชุด `stuck` | ใบ `NEEDS_REVIEW` | ด่วน |
| `pool-low` | บัญชีต้นทางใกล้หมด (ดูข้อ 4) | ไม่มี | ด่วน |
| `operate-low` | ไม่มี | ยอดใช้ได้ในสมุดใกล้หมด (ดูข้อ 4) | ด่วน |

ไม่ใส่คิวรอส่งที่เดินปกติซ้ำกับ `queue` / `waiting` เป็นแถวที่สอง

### 3.2 ช่วงล่าง — ล่าสุด (recent)

รวมเป็นรายการเดียว เรียงเวลาใหม่ก่อน ตัดเหลือ 5 แถว (เติมเงินนับใน 5 นี้)

| มาสเตอร์ | ร้าน |
|---|---|
| ชุด `SETTLED` หรือ `FAILED` จาก `updatedAt` / `settledAt` / `createdAt` | ใบ `COMPLETED` หรือ `FAILED` ของร้านตน จาก `updatedAt` / `confirmedAt` / `createdAt` |
| ไม่มีแถวเติมเงิน | บวกเหตุการณ์ `topup` ที่ seed ไว้ 1 รายการของ `m-acme` |

โทน: สำเร็จ = ปกติ, ล้มเหลว = ด่วน, เติมเงิน = ปกติ

## 4. เกณฑ์ยอดใกล้หมด

บัญชีต้นทาง (มาสเตอร์) เข้าเกณฑ์เมื่ออย่างน้อยข้อหนึ่งเป็นจริง

1. ไม่มีบัญชีต้นทาง (`effectiveSource` เป็น `null`) — ใช้ข้อความเดียวกับ `houseAlerts` ข้อ `no-source`
2. `houseAlerts` มี `short` — ยอดธนาคารไม่พอทั้งคิวบวกเงินสำรอง
3. `bankBalance < minBalance * 2` — ต่ำกว่าสองเท่าของเงินสำรอง
4. เพดานวันเหลือ `(dailyAmountCap - dailyAmountUsed) / dailyAmountCap < 0.2`

ถ้า seed ปัจจุบันไม่เข้าข้อ 2–4 และมีบัญชีต้นทาง ให้ลด `bankBalance` ใน `seed.ts` จนข้อ 3 เป็นจริงตอนเปิดมาสเตอร์ เพื่อให้แถวโชว์ในเดโม

ยอดร้าน (ร้าน Acme) เข้าเกณฑ์เมื่อ `books.operate < 50_000`

ถ้า seed ของ `m-acme` สูงกว่านี้ ให้ลด `operate` ใน `BOOK_SEED` จนแถวโชว์ตอนเปิดร้าน

## 5. จุดคลิก

ตั้ง `listPage` / `batchListPage` เป็น 1 และใช้ช่วงวันที่ `d30` เมื่อไปหน้ารายการ เพื่อไม่พลาดของค้างที่สร้างก่อนวันนี้

| แถว | มาสเตอร์ | ร้าน |
|---|---|---|
| `queue` | `/payouts/batches` · `batchStatus=PENDING` · `batchStuck=false` | `/payouts` · `statuses=["PENDING"]` |
| `waiting` | `/payouts/batches` · ถ้ามีชุด `stuck` ใช้ `batchStuck=true`; ไม่มีแล้วมี `SENDING` ใช้ `batchStatus=SENDING`; นอกนั้น `batchStatus=SENT` | `/payouts` · `statuses=["PROCESSING"]` |
| `review` | `/payouts/batches` · `batchStuck=true` ถ้ามีชุดค้าง มิฉะนั้น `batchStatus=NEEDS_REVIEW` | `/payouts` · `statuses=["NEEDS_REVIEW"]` |
| `pool-low` | `/payouts/overview` ไม่แตะตัวกรองรายการ | — |
| `operate-low` | — | `/payouts/overview` |
| ชุดสำเร็จ/ล้มเหลว | `/payouts/batches/:batchId` | — |
| ใบสำเร็จ/ล้มเหลว | `/payouts/:referenceId` | `/payouts/:referenceId` |
| เติมเงิน | — | `/payouts/overview` |

ร้านไม่มีหน้าชุดโอน ห้ามลิงก์ `/payouts/batches`

## 6. UI

- ปุ่มกระดิ่ง (`Bell` จาก lucide) ใน `Shell` ซ้ายของ `Select` บทบาท
- จุด badge เป็นตัวเลขช่วงบนเท่านั้น ถ้าศูนย์ไม่โชว์จุด กระดิ่งยังกดได้
- `Popover` align ท้าย ความกว้างประมาณ `20rem`–`22rem` (กว้างกว่าค่าเริ่ม `w-72`)
- หัวข้อ popover: «แจ้งเตือน»
- ช่วงบนมีป้าย «ต้องลงมือ» ช่วงล่างมีป้าย «ล่าสุด»
- แถวเป็นปุ่มเต็มความกว้าง หัวข้อหนึ่งบรรทัด รายละเอียดสี muted (จำนวน ยอด หรือรหัสชุด/ใบ)
- ว่างทั้งสองช่วง: «ไม่มีเรื่องที่ต้องลงมือตอนนี้»
- ว่างเฉพาะช่วงล่าง แต่ช่วงบนมีของ: ซ่อนช่วงล่าง ไม่ต้องข้อความว่าง
- ไม่มีปุ่มอ่านแล้ว ไม่มีดูทั้งหมด

## 7. โครงโค้ด

หน่วยที่แยกได้

1. `listInbox(db, args)` ใน `mock/query.ts` — คืน `{ live, recent, badgeCount }` ไม่รู้เรื่อง React
2. ประเภท `InboxItem` ใน `mock/types.ts` — `id`, `section`, `tone`, `title`, `detail`, `to`
3. `to` เป็น `{ path: string } & Partial` ของฟิลด์ตัวกรองที่ใช้จริง (`statuses`, `batchStatus`, `batchStuck`) ไม่ import `FilterProvider` จาก mock
4. อาร์เรย์ seed เติมเงินเล็กๆ ใน `mock/seed.ts` (หรือไฟล์ seed คู่กัน) มี `id`, `at`, `merchantId`, `amount`
5. คอมโพเนนต์ `NotificationBell` อยู่ `features/notifications/` อ่าน viewer + filters + navigate กดแถวแล้ว `setFilters` แล้ว `nav(path)` แล้วปิด popover
6. `Shell` วางกระดิ่งอย่างเดียว ไม่คำนวณ inbox เอง

`tone`: `alert` | `warn` | `default`

เรียงช่วงบน: ด่วนก่อน (`review`, `pool-low`, `operate-low`) แล้ว `waiting` แล้ว `queue`

ข้อความไทยยึดคำที่มีในแอปแล้ว เช่น «ส่งแล้วรอธนาคารนาน» จาก `STUCK_BATCH_LABEL` ไม่ตั้งชื่อใหม่ให้เรื่องเดียวกัน

## 8. สถานะว่างและขอบเดโม

- สลับบทบาทแล้วรายการในกระดิ่งต้องเปลี่ยนทันที ตาม `role` + `merchantId`
- มาสเตอร์ไม่เห็นเติมเงินของร้าน
- ร้านไม่เห็น pool และไม่เห็นชุดโอนร้านอื่น
- ไม่มีข้อผิดพลาดเครือข่ายใน mock ถ้า `source` เป็น null จากเดโม `noSource` ให้แถว `pool-low` ใช้ข้อความเดียวกับ `houseAlerts` ข้อ `no-source` และกดไปภาพรวม

## 9. เกณฑ์จบ

- กระดิ่งอยู่ซ้ายของ dropdown บทบาททุกหน้า
- มาสเตอร์และร้านได้รายการคนละชุดตามข้อ 3
- จุดบนกระดิ่งเท่ากับจำนวนแถวช่วงบน
- กดแถวแล้วไปถูกหน้าและตัวกรองตามข้อ 5
- แถวเติมเงินโชว์เฉพาะร้าน และกดแล้วไปภาพรวม
- ไม่มี dialog กลางจอ
