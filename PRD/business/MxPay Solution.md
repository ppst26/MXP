# Product Requirements Document (PRD)

## 1. Overview & Problem Statement

### 1.1 Problem Statement (ปัญหาและที่มาของโครงการ)
การดำเนินงานระบบรับชำระเงิน (Deposit) และจ่ายเงินออก (Payout) ด้วย **บัญชีบุคคลธรรมดา (Individual Accounts)** เผชิญข้อจำกัดรุนแรงทางธุรกิจและความเสี่ยงด้านเสถียรภาพระบบ:
* **ความเสี่ยงบัญชีถูกระงับสูง (High Account Suspension Risk):** เมื่อมีปริมาณธุรกรรม (Volume & Frequency) ถี่เกินเกณฑ์การใช้งานทั่วไปของบุคคลธรรมดา ระบบตรวจจับธุรกรรมผิดปกติของธนาคารจะทำการระงับหรืออายัดบัญชีทันที ส่งผลให้เส้นทางการเงินหยุดชะงัก
* **ข้อจำกัดเรื่องการยืนยันตัวตนด้วยใบหน้า (Face Verification Bottleneck):** การทำธุรกรรมโอนเงินออกเกิน 50,000 บาท/ครั้ง หรือยอดสะสมเกิน 200,000 บาท/วัน ติดเงื่อนไขการสแกนใบหน้าเจ้าของบัญชีจริง ทำให้ไม่สามารถพัฒนาระบบจ่ายเงินอัตโนมัติ (Automated Payout Engine) ได้อย่างต่อเนื่อง
* **ไม่รองรับการโอนเงินแบบกลุ่ม (Lack of Bulk Transfer):** บัญชีบุคคลไม่รองรับการประมวลผลคำสั่งโอนเงินพร้อมกันหลายรายการ (Batch/Bulk Processing) ทำให้เกิดคอขวดเมื่อมีคำขอถอนเงินเข้ามาพร้อมกันจำนวนมาก
* **ภาระการปฏิบัติการแบบ Manual:** ต้องพึ่งพาเจ้าหน้าที่ในการกดทำรายการโอนเงินและตรวจสอบสเตทเมนต์หน้าจอ ส่งผลให้การประมวลผลล่าช้า มีต้นทุนแรงงานสูง และมีความเสี่ยงต่อความผิดพลาด (Human Error) รวมถึงการทุจริตภายใน

---

### 1.2 Solution Concept (แนวทางแก้ไขปัญหา)
เปลี่ยนผ่านโครงสร้างพื้นฐานทางการเงินมาใช้ **บัญชีนิติบุคคล/บจก. (Corporate Banking Gateway)** เพื่อสร้างระบบ Payment Gateway กลางระดับ Enterprise:
* **ขยายขีดความสามารถและขจัดเงื่อนไขสแกนหน้า:** ปลดล็อกข้อจำกัดวงเงินโอนต่อครั้งและต่อวันในระดับองค์กร โดยไม่ต้องผ่านเงื่อนไขการสแกนใบหน้าบุคคล
* **รองรับระบบประมวลผลอัตโนมัติ (Direct API & Batch Processing):** เชื่อมต่อคำสั่งจ่ายเงิน (Payout) และระบบรับเงิน (Deposit) ผ่านสถาปัตยกรรม Direct API / Automated Matching Engine
* **ความปลอดภัยและการควบคุมสิทธิ์ระดับองค์กร:** จัดโครงสร้างบัญชีด้วยระบบแบ่งแยกหน้าที่ Dual Control (Maker-Approver) และควบคุมความปลอดภัยด้วย Hardware/Mobile Token และ Role-Based Access Control (RBAC)

### 1.3 ศักยภาพเชิงเปรียบเทียบ (Individual vs Corporate Account Comparison)

| มิติการเปรียบเทียบ | บัญชีบุคคลธรรมดา (Individual) | บัญชีนิติบุคคล บจก. (Corporate Gateway) | ศักยภาพที่เพิ่มขึ้น (ประมาณการ) |
| :--- | :--- | :--- | :--- |
| **วงเงินโอนสูงสุด / ครั้ง** | จำกัดเงื่อนไขสแกนหน้าเมื่อเกิน 50,000 บาท | 500,000 – 2,000,000+ บาท / รายการ | **เพิ่มขึ้น 10 – 40 เท่า** |
| **วงเงินโอนสูงสุด / วัน** | จำกัดประมาณ 200,000 – 2,000,000 บาท | 10,000,000 – 50,000,000+ บาท / วัน (ขึ้นกับสัญญาและประเภทธุรกิจ) | **เพิ่มขึ้น 10 – 25+ เท่า** |
| **ความถี่ธุรกรรม (Txns / วัน)** | ตรวจจับและเสี่ยงถูกระงับเมื่อเกิน 100–200 รายการ | รองรับได้ระดับหลักพันถึงหลายหมื่นรายการ / วัน | **รองรับปริมาณธุรกรรมเพิ่มขึ้น 50–100 เท่า** |
| **รูปแบบการจ่ายเงินออก** | โอนทีละรายการแบบ Manual | รองรับ Direct API Auto-Payout / Bulk Transfer | **ลดระยะเวลาการประมวลผลลงกว่า 90%** |
| **การยืนยันความปลอดภัย** | พึ่งพาใบหน้าบุคคลจริง (ขัดขวางระบบ Auto) | ใช้ Role Matrix + Dual Control + Digital Signature (Token/2FA) | **รองรับ Auto 100% โดยยังรักษามาตรฐานความปลอดภัย** |

### 1.4 Objectives & Success Metrics (วัตถุประสงค์และตัวชี้วัดความสำเร็จ)
* **Core Objective:** พัฒนาระบบ Payment Gateway ระดับ Enterprise ที่มีเสถียรภาพสูง รองรับปริมาณธุรกรรมขนาดใหญ่ ลดการพึ่งพาแรงงานคน และขจัดปัญหาบัญชีถูกระงับ
* **Success Metrics:**
  * **Deposit Auto-Matching Rate:** อัตราการจับคู่และปรับยอดยืนยันเงินฝากสำเร็จแบบอัตโนมัติ $\ge 98\%$
  * **Payout Processing Speed:** ระยะเวลาประมวลผลคำสั่งถอนเงินตั้งแต่สร้างรายการจนสำเร็จเฉลี่ย $\le 15$ วินาที/รายการ
  * **System Availability (Uptime):** ความพร้อมในการให้บริการของระบบ Gateway $\ge 99.95\%$
  * **Account Downtime Reduction:** ลดอัตราการหยุดชะงักของระบบการเงินจากการถูกอายัดหรือระงับบัญชีลง $\ge 90\%$ เมื่อเทียบกับระบบบัญชีบุคคล
  * **Throughput Capacity:** ขีดความสามารถในการประมวลผลคำสั่ง Payout พร้อมกันได้ไม่ต่ำกว่า 50–100 รายการ/นาที

### 1.5 Target Audience & Stakeholders (กลุ่มผู้ใช้งานเป้าหมาย)
* **Tenants / Merchants (ร้านค้า/แพลตฟอร์มพันธมิตร):** ผู้เชื่อมต่อ Gateway API เพื่อรับชำระเงินและสั่งจ่ายเงินออกให้สมาชิกระบบอัตโนมัติ — **1 Merchant มีได้หลายบัญชี บจก.**
* **Corporate Accounts (บัญชี บจก.):** บัญชีนิติบุคคลที่ผูกกับ Merchant แต่ละบัญชีมี Statement และ Credential ของตนเอง
* **System Operators & Approvers (ผู้ดูแลระบบหลังบ้าน):** เจ้าหน้าที่ควบคุมการเงิน ตรวจสอบ Ledger ดูแลสภาพคล่อง และอนุมัติรายการ (Dual Control Matrix)
* **Sub-Users / Operational Staff (ฝ่ายปฏิบัติการ):** **หลาย User ต่อ 1 บัญชี บจก.** — พนักงานที่มีสิทธิ์สร้างรายการ (Maker) อนุมัติ (Approver) หรือตรวจสอบข้อมูล (Inquiry Only) เพื่อกระทบยอดทางบัญชี
* **End-Users (ลูกค้าปลายทาง):** ผู้ใช้งานที่ทำธุรกรรมฝากและถอนเงิน โดยต้องการความรวดเร็ว แม่นยำ และปรับยอดเครดิตทันที
